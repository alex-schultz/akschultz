Where I go deep

Five areas I know well enough to make the hard calls in, and to teach.

  1. 01

    Frontend

    Angular, Vue, TypeScript

    Equally at home in Angular and Vue, from internal tools to revenue-critical consumer flows.

    • Subscription and checkout funnels built for experimentation
    • Real-time operational dashboards
    • Component architecture that stays maintainable as teams grow
  2. 02

    Backend and APIs

    Java, Spring Boot, TypeScript, Python, Go, Node

    High-traffic services and REST APIs that are designed, documented, tested, and observable.

    • Payment backends processing tens of millions of dollars a year
    • Database read latency cut 10× by building the metrics to find the problem
    • SSO, search, filtering, sorting, and pagination done properly
    • Legacy systems rewritten in quarters, not years
  3. 03

    Developer tooling and CLIs

    Python, Go

    Command-line tools and the APIs behind them, built for the engineers who use them every day.

    • CLIs that slot into existing developer workflows and pipelines
    • APIs designed to be scripted and automated against
    • Sensible defaults, clear output, and errors that say what to do next
  4. 04

    Cloud and platform

    AWS, Kubernetes, Helm, Docker

    Systems designed for the cloud rather than merely hosted there.

    • Event-driven workloads built on queues and streams: SQS, SNS, EventBridge, Kafka, and Lambda
    • Kubernetes deployments packaged with Helm
    • Infrastructure as code and CI/CD from day one
    • Monitoring in Datadog so problems surface early
  5. 05

    Agentic development

    Claude Code, Codex, GitHub Copilot

    I use coding agents as a daily part of how I build, and have designed and shipped services start to finish with them.

    • Services taken from design to production with agents doing much of the typing
    • Clear specs and small, verifiable steps so the agent stays on track
    • Agent output reviewed, tested, and owned like any other code

Approach

How I work

Tests come first

TDD and BDD are how I think, not a box to tick. Tests are the fastest way I know to ship with confidence.

Ship small, ship often

CI/CD and infrastructure as code from day one, so releasing is routine instead of an event.

Lead by raising the bar

As a tech lead I review carefully, pair generously, and keep the codebase somewhere people want to work.

Design for the person using it

My degree focused on human-computer interaction. I care how software feels, not just whether it works.
